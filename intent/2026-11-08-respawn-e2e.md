# Intent: Real-process respawn lifecycle verification

**Status:** Complete

## Problem statement

Unit tests cannot show whether a stopped respawn survives a real server restart,
whether another role-less process is refused, or whether a non-git idle workspace
stops cycling through a real tmux pane.

## Proposed outcome

A rerunnable `scripts/verify-respawn-lifecycle.sh [ref]` builds the selected commit
in a temporary worktree and prints observed PASS/FAIL results for all three flows.
Compare master and HEAD without spending model tokens or touching live sessions.

## Affected users and systems

Maintainers verifying RL-1, RL-4 and the established-holder portion of RL-6.
The runner uses only temporary shell sessions, servers, data, HOME and tmux socket.

## Constraints

No default socket, production data directory, model CLI, deployment or new CI gate.
Cleanup must run on failure and interruption. Dependencies are read through a
symlink to the existing installation; builds modify only the temporary worktree.

## Open questions

None. Simultaneous first lease acquisition is outside this runner's scope.

## Observed results

Master `054af7c5` fails all three scenarios: stopped state stays enabled,
a second role-less server stays alive, and a fourth unchanged cycle starts.
HEAD `23a5e6bc` passes all three: disabled state survives restart, the second
server exits 1 with its lease refusal and leaves the pane unchanged, and exactly
three unchanged cycles stop with `unchanged_workspace` and stay stopped.

Shells use the detector's prompt glyph and a half-second harmless command delay
so step completion follows delivery rather than racing the mux write. Restarts
are observed past the two-minute restore grace period. No production code or
CI gates were changed.
