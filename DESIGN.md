# Canvas design

This document records the implemented canvas surface. Product truth lives in
PRODUCT.md; the pinned composition and behavior live in
`docs/agentic-canvas/canvas-ui-ux-brief.md` and its surface brief. The rest of
Codeman retains its existing visual system.

The board occupies the document. A 192px outline overlays the left edge; a 320px
reader/Keys rail overlays the right. Closing either preserves world coordinates.
The board carries content and container titles. Object authors and dates belong
in the reader. Select, Pan and Add share the compact dock. Add opens a labeled menu; Comment remains unavailable with a keyboard-reachable explanation. Selection actions form a compact row above the dock. Editing and geometry use the reader; no permanent inspector is added.

Tokens are scoped to `html[data-canvas]` in `canvas.css`. Dark uses the pinned
matte palette. Light uses Opsdeck neutral planes. The document reads the app's
`codeman:skin` preference, including storage events from the dashboard. Imported
content is inert text in this slice. No shipping raster assets are introduced.

System sans, 14px/1.45 body, 12px supporting text and tabular monospace key hints;
16px reader text. Spacing follows 4px increments, control corners 4px and content
corners 6px. Desktop controls are at least 32px high; phone controls are 44px.
Neutral selection boundaries follow object edges with corner brackets; keyboard
focus uses an offset amber outline. Selected tools use raised neutral fill and an
amber icon. Outline selection uses a raised row; focus uses the amber outline. Inline SVG icons share a 1.5px stroke. Native inputs, caret,
selection, scrollbars and focus use the surface tokens.

The rail arrives using opacity/transform over 160ms. Content updates and camera
motion have no CSS transitions. Reduced motion removes the arrival. Phone
outline and rail are dedicated full-height views with visible close controls.
The board remains available through dismissal; neither view is modal.

Browser evidence is generated by `test/canvas-view.browser.test.ts` into ignored
`pr/media/pc3-review-<timestamp>-<state>.png` at device scale 1. The owner inspects
these captures before handoff. The coordinator owns the independent final-head
design review, dashboard baseline comparison and release verdict.

PC4 adds eight neutral resize squares (8px visible, 16px hit areas) at screen scale,
with Shift proportion and Alt center constraints. Marquee and Alt-drag selection
lasso use a 1px neutral boundary and faint neutral fill. Explicit named reparent
targets use one amber boundary and a destination name. Ordinary drags preserve
parents. Pending, saved, failed and conflicting drafts use quiet inline reader
text and explicit recovery actions. Phone layouts omit all editing controls.

`test/canvas-edit.browser.test.ts` captures both themes at 1440px into
`pr/media/pc4-review-<timestamp>-<theme>-<state>.png`. Independent design approval
remains with the coordinator.

Selection chrome clears content by 6 screen pixels at every zoom. Multi-selection keeps member corner marks and one combined boundary without handles. Amber focus clears the selection by another 3px, with 4px object and 6px container corners. Undo/redo use the dock's icon style; selection actions center 8px above the dock. Add centers on its button at the same 8px gap, uses the dock pressed state and supports arrows/Escape. Reader values use primary text; conflicts name the change writer when known and offer “Keep my draft” and “Use saved text”.
