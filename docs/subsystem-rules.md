Needs the `claude` CLI, so it is a local check, not a CI step. Don't relocate those.

## Static asset caching

The production server caches static files for 1 year, `immutable` (`setHeaders` in `server.ts`), except the `.json` data files under `public/` (`whats-new.json`, `security-notices.json`, `manifest.json`), which are served `no-cache` because they are neither content-hashed nor `?v=`-busted (pinned by `test/static-cache-headers.test.ts`). To avoid stale frontend after a deploy, `renderIndexHtml` runs `cacheBustAssets(html)` — it appends `?v=<mtime>` to **every same-origin `.js`/`.css`** reference (mtime memoized ~1s so a burst of renders is cheap; external/already-versioned/missing refs untouched). Because `index.html` is served `no-cache`, a **normal reload now picks up edited modules/styles — no hard refresh needed** (the gesture bundle is injected separately with its own `?v=`). If you add an asset referenced by an _absolute_ URL or from JS rather than a `<script>/<link>` tag, it won't be auto-busted. ⚠️ **`index.html` itself is the exception: it is read ONCE into `indexHtmlTemplate` in the `WebServer` constructor**, so editing markup in dev needs a server restart (edited `.js`/`.css` do not) — otherwise you debug a "CSS class that doesn't apply" that is really an element still missing from the served HTML.

## Common Gotchas

- **A prompt is one paste plus Enter** — `writeViaMux()` sends the text as one bracketed paste and Enter separately. ⚠️ **Input must END with `\r` or Enter is never sent**: `sendInput()` only issues `send-keys Enter` when the payload contains a carriage return, a `\r`-less `POST /api/sessions/:id/input` still succeeds (send-and-wait even reports `delivered:true`) while the text sits unsubmitted on the composer, and any `wait` burns its whole timeout on a turn that never started. Embedded newlines are kept (`\r\n` becomes `\n`): all lines go in as that ONE paste and the Enter after it submits them together, so `"echo A\necho B\r"` runs both commands in a shell. Multi-line text WITHOUT `\r` is pasted the same way. Leading and trailing line breaks are dropped. ⚠️ `SubmitVerifier` cannot reliably recognise a multi-line paste in the composer. ⚠️ **Claude Code 2.1.277+ ignores Enter for the first 30-50 s after the composer paints** while still taking the typed text, so text+`\r` sent at readiness sits unsent with `0 tokens` and a `wait` burns its timeout. So the SERVER verifies every programmatic write that carried a `\r`: `SubmitVerifier` (`session-submit-verifier.ts`, armed from `writeViaMux`) re-sends Enter only while the LAST composer line (the CLI's own `promptGlyph`) verifiably still holds the head of what was sent; an empty composer, other text, or no composer line at all ends it, and a newer write replaces the schedule. The `shift+tab` footer only means the composer painted, never that Enter is accepted. ⚠️ **A prompt must never be written into the pane as ONE burst**: Claude Code 2.1.283 takes a `<text>\r` burst of ~100+ chars as a paste, its `\r` lands as a NEWLINE and the prompt strands. So `POST .../input` routes a plain prompt (`isPlainPromptInput()`, route-helpers.ts: printable text + exactly one trailing `\r`) through `writeViaMux` even without `useMux`, AWAITED so the browser's serialized POST fallback keeps frame order; raw frames and an explicit `useMux:false` keep the direct write → [architecture-invariants#input-delivery-and-ws-resilience](architecture-invariants.md#input-delivery-and-ws-resilience)
- **ESM only** — Never `require()`, use `await import()`. `tsx` masks CJS/ESM issues in dev but production breaks
- **Package ≠ product name** — npm: `aicodeman`, product: **Codeman**. Release renames tags accordingly. Both `aicodeman` and `codeman` bin aliases are installed (`package.json` `bin`)
- **Global regex `lastIndex`** — Shared `g`-flag patterns in loops must reset `lastIndex = 0` first, or use the `execPattern()` helper in `utils/regex-patterns.ts` (resets automatically)
- **`envOverrides` flow `CLAUDE_CODE_*` / `OPENCODE_*` / `CODEX_*` / `GEMINI_*` / `GOOGLE_*` / `ANTIGRAVITY_*` / `PI_*` / `GROK_*` / `XAI_*` / `DSH_*` / `DEEPSEEK_*` / `COPILOT_*` env vars, plus exact-key `CLAUDE_CONFIG_DIR`** — Set via `POST /api/sessions { envOverrides }`, stored on `Session._envOverrides`, exported by `tmux-manager.buildEnvExports()` at spawn time, persisted in `SessionState.envOverrides`. **Do NOT** write these to `<case>/.claude/settings.local.json`. (`GOOGLE_*` is the deliberately-broad Vertex-AI namespace for Gemini — see Multi-CLI prefix discipline.) `CLAUDE_CONFIG_DIR` points a session at a separate Claude account/config dir for per-client subscriptions; it persists to state.json. ⚠️ A relocated config dir writes transcripts outside `~/.claude/projects` unless the user symlinks `projects` back into the shared tree (`ln -s ~/.claude/projects <configDir>/projects`). ⚠️ It is also one of claude's `privilegedEnvKeys`, so in multi-user mode setting it via `envOverrides` is admin-only, and a non-granted owner's already-persisted `CLAUDE_CONFIG_DIR` is stripped on reboot-restore (see `session-env-clamp.ts`). → [architecture-invariants#per-session-env-overrides-exact-key-allowlist-and-claude_config_dir](architecture-invariants.md#per-session-env-overrides-exact-key-allowlist-and-claude_config_dir)
- **Effort is NOT an env var** — never carry effort as `CLAUDE_CODE_EFFORT_LEVEL`: the env var hard-locks effort and blocks in-session `/effort` switching (incl. ultracode). It flows as the dedicated `effort` payload field → `Session._effort` → `claude --effort <level>` for regular levels incl. `max` (the settings `effortLevel` key is `enum(["low","medium","high","xhigh"]).catch(undefined)` — `max` gets SILENTLY dropped there), or `claude --settings '{"ultracode":true}'` for ultracode (rejected by `--effort`). Both are soft defaults the user can override anytime. Legacy env-var entries are auto-migrated by the Session constructor and unset from tmux sessions in `applyEnvOverrides()`. See `buildEffortCliArgs()` in `session-cli-builder.ts`, tests in `test/effort-injection.test.ts`
- **The advisor rides `--settings`, NEVER the `--advisor` flag**: Claude Code's advisor tool flows as the `advisorModel` payload field → `Session._advisorModel` → the `advisorModel` key in the launch's ONE `--settings` JSON, merged with ultracode and the statusLine exporter by `buildAdvisorSettings()` (`session-cli-builder.ts`). ⚠️ The flag EXITS at launch on any pairing the CLI refuses, which would leave a dead pane on every respawn; the settings key degrades to "no advisor" instead. ⚠️ `isAdvisorModel()` (fable/opus/sonnet aliases or full ids, no haiku) is also the injection guard for the single-quoted argument. Soft default: `/advisor` still switches it in-session. App Settings key `claudeAdvisorModel` (SYNCED, `''` = leave it to the CLI). Remote/docker quick-start refuses it, like `effort`, and so does a remote attach on `POST /api/sessions`. → [architecture-invariants#advisor-model](architecture-invariants.md#advisor-model)
- **Model choice: a persistent default in `settings.local.json`, a per-session `--model`, never env** — the App Settings **Claude Model** picker (`claudeModel` in `settings.json`) is read by `session-ui.js` at session create, sent as the `modelOverride` payload field, and `updateCaseModel()` (`hooks-config.ts`) writes/deletes the `model` key in `<case>/.claude/settings.local.json`. This is the intended exception to the envOverrides rule above: model legitimately lives in `settings.local.json` (a soft default — in-session `/model` still works); env vars do not. A caller that wants one session on a model without touching the case sends `model` on `POST /api/sessions` instead: it goes out as `claude --model <id>`, writes nothing, wins over the app-wide default, and is persisted as `SessionState.model` so both recovery paths relaunch on it. ⚠️ Claude only, via the `model.source` capability (`cliTakesSessionModel()`), never a mode check: refused for other CLIs and on a remote attach, and published by `toState()` for claude alone. → [architecture-invariants#model-choice](architecture-invariants.md#model-choice)
- **Multi-CLI prefix discipline** — env-var prefix is CLI-specific (`CLAUDE_CODE_*` vs `OPENCODE_*` vs `CODEX_*` vs `GEMINI_*` vs `ANTIGRAVITY_*` vs `PI_*` vs `GROK_*` vs `DSH_*` vs `OMP_*` vs `COPILOT_*`) and the `ALLOWED_ENV_PREFIXES` allowlist in `schemas.ts` enforces this; non-prefix exceptions are exact keys in `ALLOWED_ENV_KEYS` (currently only `CLAUDE_CONFIG_DIR`), never a widened prefix. Gemini additionally allowlists the **broad `GOOGLE_*`** namespace, and Grok allowlists **`XAI_*`** for the same vendor-namespace reason. When adding a setting, decide which CLI(s) it applies to and gate the env export accordingly. Never blanket-forward all prefixes. ⚠️ Pi is the case that proves the rule: its ~34 provider keys share NO prefix — they stay out, and pi users authenticate via `/login` or the server process's own env. ⚠️ DeepSeek repeats pi's lesson exactly: a dsh `settings.yaml` can nominate ANY env var as a provider credential (`apiKeyEnv`), so only the vendor namespaces `DSH_*` and `DEEPSEEK_*` are admitted; foreign provider keys authenticate from dsh's own files or the server env. Resolver design pattern: `docs/opencode-integration.md`, `docs/pi-integration.md`, `docs/grok-integration.md`, `docs/deepseek-integration.md`, `docs/omp-integration.md`, `docs/copilot-integration.md` → [architecture-invariants#per-session-env-overrides-exact-key-allowlist-and-claude_config_dir](architecture-invariants.md#per-session-env-overrides-exact-key-allowlist-and-claude_config_dir)
- **Zod `.optional()` rejects `null`** — accepts `undefined` only. When the frontend builds a request body with `JSON.stringify`, an explicit `null` field is preserved on the wire and fails validation with `INVALID_INPUT`. Convert `null` → `undefined` before stringifying (e.g. `field: value ?? undefined`), or declare the schema `.nullish()`. This has caused real shipped bugs twice
- **Local-echo overlay stays on screen**: the overlay lays its wrapped lines out DOWNWARD from the prompt row, and the text has not reached the PTY yet, so the CLI never learns the prompt is long and nothing scrolls to make room. The block now grows UPWARD once it would pass the last visible row, and a prompt taller than the viewport keeps its TAIL. ⚠️ Separately, `_shrinkPaddingToFit()` (mobile-handlers.js) must never shrink `main`'s padding-bottom below the MEASURED height of the fixed bars. → [architecture-invariants#xterm-zerolag-input-is-single-source](architecture-invariants.md#xterm-zerolag-input-is-single-source)
- **`xterm-zerolag-input` is single-source** — BOTH echo addons live ONLY in `packages/xterm-zerolag-input/src/`, bundled into TWO **gitignored** vendor files: `vendor/xterm-zerolag-input.js` and `vendor/xterm-predictive-echo.js` — dev by `scripts/postinstall.js`, prod by `scripts/build.mjs`. `app.js`/terminal-ui.js only **consume** them via `new LocalEchoOverlay(terminal)` / `new PredictiveEchoOverlay(terminal)`; there is no inline copy. So: change the package source, then rerun the bundle step (`npm install` for dev, `npm run build` for prod). **Never hand-edit `app.js` for overlay behavior, and never commit the gitignored vendor bundles.** Always test on mobile after touching it. → [architecture-invariants#xterm-zerolag-input-is-single-source](architecture-invariants.md#xterm-zerolag-input-is-single-source), `docs/local-echo-overlay-plan.md`
- **Default bind is loopback-only; non-loopback without a password starts but warns** — the server defaults to `--host 127.0.0.1`. Binding non-loopback (`--host`/`-H`/`CODEMAN_HOST`) without `CODEMAN_PASSWORD` starts anyway but prints a loud warning; `--allow-unauthenticated-network` / `CODEMAN_ALLOW_UNAUTHENTICATED_NETWORK=1` acknowledges it. ⚠️ The production systemd unit passes no `--host`, so prod binds **localhost only**: reach it via `tailscale serve`/tunnel to `127.0.0.1`. A loopback bind is reachable through a same-host tunnel but NOT by a browser hitting the box's LAN IP. `install.sh` is separate and prompts for the binding, and preserves the existing binding on re-runs. → [architecture-invariants#default-bind-and-the-non-loopback-warning-path](architecture-invariants.md#default-bind-and-the-non-loopback-warning-path), `docs/security-architecture.md`
- **Instance isolation / multi-instance attach danger** — the data dir (`~/.codeman`) and tmux socket (`tmux -L codeman`) are PROCESS-WIDE and shared by every Codeman on the machine, derived from `CODEMAN_INSTANCE` via `src/config/instance.ts`. ⚠️ A 2nd instance on the SAME socket **discovers and attaches PTYs to the first instance's live sessions**, resizing and mutating them. `$HOME` isolation is NOT enough because tmux is system-global. To run two instances, give each a distinct `CODEMAN_INSTANCE` (scopes dir + socket together), or set `CODEMAN_TMUX_SOCKET` + `CODEMAN_DATA_DIR` individually; `scripts/run-beta.sh` does this for a beta alongside prod. ⚠️ Being the **live** deploy colour (the default with no `CODEMAN_DEPLOY_ROLE`) is a LEASE: `deploy-lease.json` in the data dir names one pid + start time (`src/deploy-lease.ts`). A live-by-default start whose lease a live Codeman holds REFUSES to start, naming the owner and telling you to set `CODEMAN_INSTANCE`; a dead/recycled holder is taken over. Candidates hold nothing; promote and reinstate acquire (refused while another live Codeman holds it), retire and stop release. **Any new `~/.codeman/...` path MUST go through `dataPath()`**, never `join(homedir(), '.codeman', …)`, and **any new `tmux -L` caller through `resolveTmuxSocketName()`** (both in `config/instance.ts`). → [architecture-invariants#instance-isolation-and-the-multi-instance-attach-danger](architecture-invariants.md#instance-isolation-and-the-multi-instance-attach-danger)
- **The prefix table on Codeman's socket holds only `<prefix> send-prefix`** — browser tabs are tmux attach clients, and tmux's stock bindings let Ctrl+B `)`/`s` move a tab onto another session. `createSession` resets the table, and `reconcileSessions()` at boot for sessions that survived an upgrade (`src/tmux-prefix-table.ts`); `root` and `C-<letter> detach-client` are left alone, so F1 and that alias reach browser tabs for the length of an attach. Alt+1..9 are `if-shell` bindings that `switch-client` only for the TUI's own client, so a browser tab's Esc-then-digit does not move it. Docker and owned-remote nested servers get the same reduction (`C-q send-prefix` only) in their create chain. ⚠️ So `Ctrl+B d` does not exist there: anything attaching a user's terminal claims its own detach key (F1 in `root`, as `codeman tui` and `scripts/tmux-manager.sh` do). → [architecture-invariants#the-prefix-table-on-codemans-socket-holds-only-send-prefix](architecture-invariants.md#the-prefix-table-on-codemans-socket-holds-only-send-prefix)
- **node-pty's macOS `spawn-helper` ships without `+x`**: `node-pty@1.1.0` publishes `prebuilds/darwin-<arch>/spawn-helper` as mode 0644, and macOS launches every PTY through it, so a stock macOS install fails every session start with `Error: posix_spawnp failed.` **Linux can never reproduce it**. ⚠️ Since Linux has no prebuild, `npm install` **needs a C/C++ toolchain there** (`make`, `g++`, `python3`), so `install.sh` checks for and installs one alongside Node/tmux/git. Do not drop that step. ⚠️ Look in **`prebuilds/<platform>-<arch>/`**, not just `build/Release/`, which does not exist on macOS. Repair is a chmod, never a mandatory rebuild: `npm run fix:node-pty` chmods every helper then proves it by really opening a PTY. `spawnPtyWithHelperRepair()` (`utils/node-pty-repair.ts`) wraps every `pty.spawn()` in `session.ts` and self-heals a broken install on the first failure. → [architecture-invariants#node-ptys-macos-spawn-helper-must-be-executable](architecture-invariants.md#node-ptys-macos-spawn-helper-must-be-executable)
- **User-chosen paths are probed BOUNDED, never with `existsSync`/`statSync`** (#516): a linked case or a `workingDir` can sit on a network mount that stopped answering. A synchronous check there freezes the whole server, and an unbounded async `stat`/`lstat`/`readFile` holds one of libuv's threadpool workers until the mount returns. On a request or spawn path use `probePath()`/`probePathKind()` (`utils/bounded-path-probe.ts`, read its `@fileoverview`). ⚠️ `unknown` is NEVER `absent`: nothing is created, scaffolded or 404'd on it. Bulk scans keep the stall cap; a request for ONE path the user named may pass `{ pastCap: true }`; and a helper that would otherwise touch the path skips whatever is still `unknown`. User-facing errors for it go through `describeUnknownPath()`, so a refused probe is not reported as a broken folder. → [architecture-invariants#user-chosen-paths-are-probed-bounded](architecture-invariants.md#user-chosen-paths-are-probed-bounded)
- **Headless screenshots: `deviceScaleFactor` MUST be 1, and write unique filenames** — under DSF=2 xterm's WebGL renderer draws glyphs at ~2× nominal size while still *reporting* nominal cell dims, so only the pixels reveal it and only the terminal font looks wrong. And overwriting a fixed output path leaves OS image viewers showing the old render, which reads as "the fix didn't work"; `scripts/capture-real-overview.mjs` mints a timestamped filename per run. Seed the per-device `localStorage` keys (`codeman:skin`, `codeman-font-size`, `codeman-app-settings`) so the capture matches a real device. → [architecture-invariants#headless-screenshot-capture](architecture-invariants.md#headless-screenshot-capture)

### Key Patterns

**Input**: `session.writeViaMux()` for programmatic/curl input via one tmux bracketed paste (`paste-buffer -p`) + `send-keys Enter`; a multi-line prompt keeps its line breaks inside that paste. A single character is typed with `send-keys -l` instead, because selection dialogs ignore a pasted digit. Interactive **browser** input goes through a durable **exactly-once** layer: a stable `clientId` + monotonic per-session `seq` persisted to localStorage until the server ACKs, so a dropped link cannot lose or double-deliver a prompt. `ws-connection-registry.ts` supersedes only same-TAB reconnects, so two tabs on one session coexist. → [architecture-invariants#input-delivery-and-ws-resilience](architecture-invariants.md#input-delivery-and-ws-resilience)

**Agent wait primitives**: bounded long-polls: `GET /api/sessions/:id/wait`, `GET .../wait-output` (literal substring, **never** regex) and `wait`/`waitTimeout` on `POST .../input`. Registry `session-wait-registry.ts` (pure), bounds `config/agent-wait.ts`. ⚠️ A timeout is a 200 (`wait.timedOut`). ⚠️ `stop` exists for `claude` and `deepseek` ONLY (rule lives in `hooksAvailableForMode()`), `blocked` also for a CLI declaring `capabilities.workDetect.blockedLine` (codex, read off the screen; `blockedSignalAvailable()`): explicit request elsewhere is a 400. ⚠️ Send-and-wait registers the waiter BEFORE the write; teardown must `notifySignal('exit')` BEFORE `cancelAll()`; hangup abort listens on `reply.raw` (guarded by `writableFinished`), never `req.raw`; liveness comes from `isPaneDead`, never `session.pid`. ⚠️ Signals are edge-triggered with no history: gather fan-outs via send-and-wait or `wait-output` markers. Packaged as the `skills/codeman` skill (injection behind `agentSkillEnabled`, SYNCED, default OFF, into `capabilities.agentSkillDir`): injection is add-only, marker-owned (`applyAgentSkill`), refuses symlinks, and refreshes a marker-owned user-level copy (`refreshUserAgentSkill`). → [architecture-invariants#agent-wait-primitives](architecture-invariants.md#agent-wait-primitives), `docs/api-reference.md`

**Agent CLI (`codeman agent …`, `src/cli-agent.ts`)**: the command-line client for the wait primitives and the session verbs, for agents the skill does not reach. It is an HTTP CLIENT: inspection and guarded stage/submit use the ownership-checked `agent-session-routes.ts` module (experimental, behind `agentCoordinationEnabled`, SYNCED, default OFF); the other verbs reuse existing routes, with no second transport, every call carries `X-Codeman-Parent-Session`, only `spawn`'s quick-start carries `X-Codeman-Agent-Origin`, and `spawn` refuses (exit 4, before any request) an empty `--working-dir` and a bare spawn from a HOME cwd. ⚠️ Three guards live in code, not prose, and the tests pin them: refuse without `CODEMAN_MUX=1`+`CODEMAN_API_URL` (never guess a URL); `send` transmits printable text + `\r` only (`inputRefusal`: any byte < 0x20 or DEL refuses BEFORE the transport), ESC exists solely as `interrupt` with no `\r`; `rm` fails closed (`deleteRefusal`: empty id, self shorter than 8, prefix match in EITHER direction, re-checked on the resolved id). ⚠️ The routes accept FULL ids only while `ls` prints prefixes, so `resolveSessionId` maps a short id through `GET /api/v1/sessions` and refuses an ambiguous one. It also refuses any id under 8 characters (exit 4, on every verb, before any request). ⚠️ A 400 for `--until stop` on a hook-less mode is passed through verbatim, never papered over: the marker path is the answer there. `spawn` on a readiness timeout exits 2 and LEAVES the session for inspection; its stdout is the id ALONE so `SID=$(…)` works. ⚠️ Two server answers that look like success and are not: `delivered:false` without `duplicate` and `wait.ended:true, signal:null` — both exit 3, checked BEFORE the happy paths in `waitExitCode`. `preview add|ls|rm|logs` act on the caller's OWN session's previews: ⚠️ `--cmd` is ONE quoted argument, and stray positional words after `<name>` refuse before any request (`previewAddExcessArgs`). The skill and the case template (`src/templates/case-template.md`) tell agents to start a server ONLY through `preview add`, bound to `127.0.0.1`, in the foreground (never `&`, `nohup`, `setsid`, `tmux`). → [architecture-invariants#agent-cli-codeman-agent](architecture-invariants.md#agent-cli-codeman-agent), README "`codeman agent`", `docs/api-reference.md`

**MCP server (`codeman mcp`, `src/mcp-server.ts`)**: a Model Context Protocol server on stdio for any MCP client, a CLIENT of the HTTP API like `codeman agent` (reuses its `httpRequest`, `inputRefusal`, `buildSendBody`; the MCP server adds no routes). ⚠️ Dual-era: answers the legacy `initialize` handshake AND the 2026-07-28 revision; a modern `tools/list`/`server/discover` MUST carry `ttlMs` + `cacheScope`. ⚠️ stdout is protocol only; logs go to stderr. ⚠️ The URL comes from `--url`/`CODEMAN_API_URL`, never a guess, and unconfigured it still lists tools while every call answers how to configure it. ⚠️ Prompt/interrupt/delete only sessions the PROCESS started (in-memory allowlist, so a restart fails closed) or, inside a pane, the calling session's own children, unless `--allow-any-session`; never its own session. ⚠️ `read_output` returns text ONLY, no `structuredContent`. ⚠️ `logs_query` is the eleventh tool and also returns text ONLY, no `structuredContent`. Waits default 45 s. → [architecture-invariants#mcp-server-codeman-mcp](architecture-invariants.md#mcp-server-codeman-mcp)

**Redacted log query** (`src/telemetry-redact.ts`, `src/telemetry-query.ts`): `redactLogLine()` masks a value whose key contains a credential word (`auth`, `password`, `secret`, `token`, `key`, `credential`, any length, with or without separators), a bearer token of any length (one placeholder when that token is also a credential-header value, so `Authorization: Bearer …` is `Authorization: [redacted]`), URL userinfo of any length, and the hook secret, before a telemetry line is queued. `queryLogs()` applies the same function again on the way out. The masked span is the whole value: a quoted value through its closer, a brace or bracket through its match, and any other value through the newline or the `}` or `]` that closes the surrounding structure. A value is never one word. `cookie`, `set-cookie`, `codeman_session`, and `sid` are secret keys; `session`, `sessionId`, `session_id`, and `claudeSessionId` are not. A token-count key (`tokens`, or a normalized name ending in `tokens`, `tokencount`, `tokenusage`, `tokenlimit`, or `tokenbudget`, such as `inputTokens`, `output_tokens`, `max_tokens`, and `tokenCount`) is not secret when its first value token is a number (digits, optional `.` `,` `_` separators, optional `k` or `m`), so `tokens: 15234 input, 921 output` and `tokens: 174k` stay. A glued value such as `tokens: 1synthetic…` is masked. That key is still masked when the value is an object, an array, or a quoted string. A key that also contains `auth`, `access`, `refresh`, `secret`, `bearer`, `api`, `session`, or `id_token` stays secret (`token`, `access_token`, `refreshTokens`, `authTokens`). Known tokens are masked with no key: `sk-` plus 20 token characters, `ghp_`/`gho_`/`ghu_`/`ghs_`/`ghr_` plus 30, `github_pat_` plus 20, `xox[abprs]-` plus 10, `AKIA` plus 16 upper-case alphanumerics, and a three-part JWT starting `eyJ`. A curl `-u` or `--user` argument is masked. A key may start with a digit. A key longer than 256 characters is treated as secret and is not copied or normalised again. The inside of a quote that is not itself a secret value is scanned for the same assignments and URL shapes, four levels deep; past that, a marked interior is masked whole. URL userinfo is masked through the last `@` before the authority ends. A `host:port` with no `@` stays, and so do a path-like key's line and column (`file.ts:247:27`) and an `Error:` label. The only keys left intact are an exact allowlist after case and separators are normalised: `author`, `authors`, `authored`, `authoredBy`, `authorId`, `authorName`, `authUser`, `auth_user`, and the snake, kebab, and camel spellings of those. An ordinary word that contains `key`, such as `keyboard`, is a credential key. Config backup's `SECRET_KEY_RE` is a separate rule and still matches `author`. What this does not catch: a secret with no credential key, no bearer scheme, no URL userinfo, no hook-secret value, and none of the token shapes above is not recognised. The redactor is a second line behind not logging secrets in the first place. The match is a literal substring, with a row cap. Each generation is read from its tail. A window that starts on a newline keeps that row; a window that starts mid-line drops the partial row. The hook secret is read with a capped read, a miss is not cached, and `getHookSecret()` supplies the value it just stored. Once that value is known, later lines do not read the file. `GET /api/logs` uses the `ApiResponse` envelope and is admin-only in multi-user mode; with no log directory it returns an empty list and a reason. There is no way to read an unredacted line. `ui-events.jsonl` is posted through `POST /api/client-errors` with `kind: "ui"`. → [architecture-invariants#redacted-log-query](architecture-invariants.md#redacted-log-query)

**Agent-created case marker** (`src/agent-case-marker.ts`): a case dir that `POST /api/quick-start` CREATES for an agent-driven spawn gets `.codeman-agent-case.json`, published as `agentCreated` on `GET /api/cases`; `GET /api/cases/agent-created` is the cleanup listing behind Add Case → Manage. ⚠️ Only the branch that CREATES the directory may write it: never label a linked case, cloned repo or pre-existing path (it drives a recursive delete). ⚠️ Reading is total: anything but a well-formed v1 marker reads as not agent-created. ⚠️ Removal stays on `DELETE /api/cases/:name` (the ONE recursive-delete path), and the sweep excludes `inUse` cases. ⚠️ Changing the preamble's headers requires bumping `CODEMAN_PREAMBLE`. → [architecture-invariants#agent-created-case-marker](architecture-invariants.md#agent-created-case-marker)

**Agent preamble cache GC**: the §0 preamble seeded per local session whose CLI takes the skill (`capabilities.agentSkillDir`) (`$XDG_CACHE_HOME/codeman-agent-<id>.sh`) is now REMOVED with the session (`removeAgentSessionPreamble` from `_doCleanupSession`, `killMux` only) and swept at boot (`pruneAgentSessionPreambles(this.sessions.keys())`). ⚠️ The sweep needs BOTH guards — never a live session's file at any age, and `AGENT_PREAMBLE_MAX_AGE_MS` (7d) of age on top, which is what keeps ANOTHER instance's sessions out of the blast radius. Losing one is degradation, not breakage: the §0 fallback block rewrites it. → [architecture-invariants#agent-preamble-cache-gc](architecture-invariants.md#agent-preamble-cache-gc)

⚠️ **A turn that ENDED waiting for its own workers is working, not idle.** Claude closes such a turn with `✻ Waiting for 1 dynamic workflow to finish` (background agents / ultracode) and resumes by itself; `capabilities.workDetect.awaitingLine` makes the idle probe count it as work. ⚠️ Claude never redraws that row, so it stays on screen after the workers finish: test it ONLY as the newest column-0 row above the composer (`isAwaitingWorkers()`), never pane-wide and never on the stream. → [architecture-invariants#idle-detection-composer-glyph-and-working-line](architecture-invariants.md#idle-detection-composer-glyph-and-working-line)

Only `idle` is eligible, and the label is pane-derived and prompt-injectable, so a pattern must anchor on chrome only that CLI draws. → [architecture-invariants#the-watching-signal-a-quiet-pane-that-is-not-waiting-for-you](architecture-invariants.md#the-watching-signal-a-quiet-pane-that-is-not-waiting-for-you). **Orchestrator**: State machine that turns a user goal into a phased plan and drives it to completion: `idle → planning → approval → executing → verifying → (replanning) → completed/failed`. `OrchestratorLoop` (engine) delegates plan generation to `orchestrator-planner` and per-phase verification gates to `orchestrator-verifier`, executing phases via team agents/`task-queue`. State persists under the `orchestrator` key in `state.json`. Distinct from Ralph (single-session autonomous loop) — orchestrator coordinates multi-phase, multi-agent execution. **Cron (`CronJob`s)**: saved, named jobs on a recurring schedule (`once`/`interval`/`daily`/`weekly`) with per-job run history. ⚠️ **Distinct from the legacy `ScheduledRun`** (`/api/scheduled`, a run-now duration-bounded loop); the two never interact and keep separate `Scheduled*` / `Cron*` names. `CronService` **reuses the existing session layer** rather than rebuilding tmux logic. **Remote sessions + remote SSH cases**: a case can point at a remote host. The agent runs in a durable remote `tmux -L codeman-remote`, fronted by a LOCAL tmux pane running `ssh`. Attached (`owned:false`) sessions **detach, never kill**; owned ones propagate `kill-session`. Auto-reconnect (`remoteAutoReconnect`, default ON) revives ONLY when `remoteTmuxSessionAlive()` proves the remote session alive. ⚠️ Classify that probe by EXIT STATUS (`classifyRemoteAliveExit`), never stdout. ⚠️ **Command-injection surface: every ssh command line must flow through `buildSshConnectionArgs()`**; never hand-build one. ⚠️ Remote file reads take browser paths only as `shellescape`d tokens, resolve symlinks fail-closed, cap on the REMOTE size, never copy to local disk, are bounded by `src/remote-ssh-limiter.ts`, and pick the host from the SESSION, never the path; no writes over ssh (the `PUT` guard must precede local path validation). ⚠️ Route remote cases through `POST /api/quick-start`, not `POST /api/sessions`. → [architecture-invariants#remote-sessions-over-ssh](architecture-invariants.md#remote-sessions-over-ssh), [#remote-ssh-cases](architecture-invariants.md#remote-ssh-cases), `docs/remote-sessions.md`

**Wake-on-LAN (`remote-wake.ts`)**: optional `RemoteHost.wakeMac` (magic packet) or `RemoteHost.wakeCommand` (single executable, no shell, takes precedence) lets HTTP input, `POST /api/sessions/:id/wake` and the user's create/attach (`ensureHostAwake`) wake a sleeping host. ⚠️ Only an explicit user request may wake: never give the registry to the auto-reconnect watcher, `handleRemoteSessionDropped`, boot recovery or `cron-service.ts`, and `GET /api/sessions/:id/reachability` must never wake. ⚠️ Detection is a throttled bare TCP probe; never add `ServerAliveInterval`, and a `jumpHost`/`socksProxy`/`ProxyCommand` host is reachability-UNKNOWN (`isProbeable()`): never buffer, gate or banner on it. ⚠️ In multi-user mode a non-admin attach 403s BEFORE host lookup. ⚠️ WS keystrokes bypass the registry, so the banner (`host-wake-ui.js`) must not promise queued input. → [architecture-invariants#remote-ssh-cases](architecture-invariants.md#remote-ssh-cases)

**Docker cases**: a case can point at a **container** running any CLI mode inside it, a **LOCATION OVERLAY on cases, never a `SessionMode`**. One long-lived container **per case**, shared by its sessions: killing a session kills only its in-container tmux, **never** `docker stop` while siblings remain. The workspace is bind-mounted at the **same absolute path**. Credentials are **seeded**, never shared RW. **NEVER a create-time `-e` for secrets, NEVER `--privileged`, NEVER the docker socket.** A drifted config (label hash) REFUSES the launch. ⚠️ An **adopted** container (`DockerCase.owned === false`) is only `exec`ed into: never create, start, stop, restart, remove, `docker commit` or `docker pause` it; fail closed. Test `owned === false`, never truthiness. ⚠️ Apply `owned` AFTER `dockerConfigHash`. ⚠️ Run modes come from the CONTAINER (`availableModes`), and a failed probe is normal for an OWNED case. ⚠️ Root exec user drops the bypass flag via the registry's `overlays.docker.rootCommand`, never a branch. ⚠️ Adoption is admin-only in multi-user mode. ⚠️ Loopback prod needs `CODEMAN_DOCKER_BRIDGE_HOOKS=1` for in-container hooks. → [architecture-invariants#docker-cases](architecture-invariants.md#docker-cases), `docs/docker-cases.md`

**Docker Compose deployment** (`docker/`): Codeman runs in a container and spawns Docker cases as **SIBLING** containers via the host socket, never nested. `resolveDockerDaemonMountSource()` maps HOME bind sources into the daemon's namespace (`CODEMAN_DOCKER_HOST_HOME`); `CODEMAN_CASES_PATH` makes workspaces resolve to the same absolute path on both sides. ⚠️ `CODEMAN_CASES_PATH` must move every consumer: resolve it only via `config/cases-dir.ts`. ⚠️ `.dockerignore` matches whole paths: keep `**/.env` or `docker/.env` secrets ship in the image. ⚠️ Long-form binds create missing sources ROOT-OWNED: `Start-Codeman.sh` pre-creates them, and `docker/entrypoint.sh` (root, `cap_add: [CHOWN, DAC_OVERRIDE, KILL, SETGID, SETUID]` against `cap_drop: ALL`, `KILL` for tini; pinned by the test) fixes ownership then drops to `PUID:PGID` via `setpriv`, never re-owning foreign dirs. ⚠️ Append `/opt/codeman-cli` and `~/.local/bin` to `PATH`, never prepend. ⚠️ `server.Dockerfile`, the compose file and `.env.example` feed the self-updater's environment gate (`docs/docker-self-update.md`). → [architecture-invariants#docker-compose-deployment](architecture-invariants.md#docker-compose-deployment), `docs/docker-compose.md`

**CLI registry** (`src/config/cli-registry/`): every run mode is a `CliEntry`. **No code outside `stock.ts` may branch on a CLI id**: use a capability field or a NAMED PROFILE (`profiles.ts`); `test/cli-registry-no-id-branching.test.ts` and `test/frontend-cli-no-id-branching.test.ts` enforce it. ⚠️ Config holds typed argv tokens, never shell text; literals are validated at LOAD time and a bad one rejects the whole entry. ⚠️ Keep `external`, `hooks` and `altScreen` independent; never derive one from another. ⚠️ Config regexes must compile through `compileVersionRegex()`. ⚠️ `privilegedParams[].param` names a LAUNCH PARAM, not the legacy `<Mode>Config` field (bridged only by `launch.legacyConfigAliases`); a wrong name silently clamps nothing. ⚠️ Resolve the registry AT CALL TIME, never in a module-level const. ⚠️ Remote claude/omp arms of `buildRemoteLaunchCommand` are not covered by the pane-command golden. `~/.codeman/clis.json` overrides entries. It is WRITTEN only by the opt-in CLI management routes, and only through `mutateRegistryFile()` in `registry-writer.ts` (the one exception: a config-backup restore of `clis.json`, which then calls `reloadCliRegistry()`), which serializes mutations and refuses (409) a file that does not parse or has group/world permission bits rather than overwriting it. Importing the registry still writes nothing. → [architecture-invariants#cli-registry](architecture-invariants.md#cli-registry), `docs/cli-registry.md`

**External CLI modes (OpenCode, Codex, Gemini, Antigravity, Pi, Grok, DeepSeek, OMP, Copilot)**: `isExternalCliMode()` in `session.ts` gates Claude-specific behavior off; work detection is per-CLI `capabilities.workDetect` data, not this gate. **Case rename** (`POST /api/cases/:name/rename`, `src/case-rename.ts`; `docs/wiki/Core-Concepts.md#case`): a case under the cases dir is its folder name and always moves; a linked case renames its alias and moves its real folder only with `renameFolder`; remote and Docker cases are refused. ⚠️ A folder that sessions have open is the hazard: live sessions at or under it make the route answer `409 requiresStop` with their names, and only `stopSessions: true` ends them; the free-target pre-check runs before that and refuses a dangling symlink too, so no session is ended for a move that cannot happen. `withCaseLock` holds the old and new paths for the whole operation. ⚠️ A create awaits the owner's layout lock and a settings read between `new Session` and the server's map, where the rename looks for open sessions, so the constructor also records the session (`noteCaseSessionStarting`) until `registerSessionWithLayout()` or `stop()` settles it, and a folder move refuses `409` with `renameCode: "BUSY"` while one is recorded at or under the folder; an alias-only rename is not refused. **Preview servers** (`src/preview-supervisor.ts`, `src/preview-proc.ts`, `routes/preview-routes.ts`; `PUT`/`GET`/`DELETE /api/sessions/:id/previews/:name`, `GET /api/previews`): an agent's dev server that CODEMAN starts and shows through a session-origin web tab the route stamps from the URL's session. Nothing restarts a preview whose session was deleted; a detach or a Codeman restart leaves it running. ⚠️ A stop finds processes three ways, never by ancestry: the process group (only while the leader's `startTicks` match the record), every process of Codeman's uid whose `/proc/<pid>/environ` carries `CODEMAN_PREVIEW_ID` AND this data dir's `CODEMAN_PREVIEW_OWNER` (never sweep on the id alone), and the port's listener only if it carries that marker. Never signal a pid whose `startTicks` changed (`signalIfSame`). ⚠️ `send()` is the ONE path to `process.kill` in the supervisor, and it asks `mayAct` (deploy role `persist`) in the same tick as the kill; never add a kill that bypasses it. ⚠️ A server the command handed off is never signalled; every stop re-checks the port and reports a listener as `leftRunning` (an `exited`/`stopped` preview as `stillListening`) in the answer, the preview log and the lists until the port is free. Never answer a stop as clean without that check. → [architecture-invariants#preview-servers](architecture-invariants.md#preview-servers), `docs/web-tabs.md#previews`

**Multi-user mode** (opt-in `--multiuser` / `CODEMAN_MULTIUSER=1`, OFF by default): named users with scrypt-hashed passwords in `~/.codeman/users.json`. Gated everywhere by `isMultiUserMode()`; when OFF, behavior is byte-identical to single-user because every scoping helper short-circuits. ⚠️ **Not a security boundary at the agent layer**: every session still runs as the SAME OS account. This separates WORKSPACES; it does not sandbox users (Docker cases are the isolation story). Ownership threads through `Session.owner` and is enforced in `findSessionOrFail`, list endpoints, SSE routing (fail-closed), WS, search, and file-preview. ⚠️ `settings.json` is ONE server-wide file, so every write to it is admin-only (`PUT /api/settings`, `/api/execution/model-config`, `/api/cases/order`, plus `PUT /api/config`: 403 `FORBIDDEN` before parsing), a non-admin's quick-start/Ralph start skips `lastUsedCase`, its GET hides `voiceSettings.apiKey`/`caseOrder`/`lastUsedCase` from a non-admin (`settingsForNonAdmin`), and the browser skips those writes for a non-admin via `_settingsReadOnly()`. System ops are admin-only too (`/api/system/update`, `/api/system/span-displays`, `/api/tunnel/qr/regenerate`, `/api/cleanup-state`), and a non-admin's `/api/auth/revoke` revokes only their own logins. → [architecture-invariants#multi-user-mode](architecture-invariants.md#multi-user-mode), `docs/multi-user-plan.md`

**Away digest**: `GET /api/away-digest` aggregates what happened while you were away from the lifecycle log, run-summary events, live sessions, token stats, and recent subagents. Pure aggregator in `web/away-digest.ts`. ⚠️ Returns `{success:true,digest}`, a legacy raw-ish shape consistent with the other raw GET handlers in `system-routes.ts`; frontend and tests read `.digest`. → [architecture-invariants#away-digest](architecture-invariants.md#away-digest)

**Ralph todo-config**: per-session `maxTodos` (FIFO-eviction cap, default 500 = `MAX_TODOS_PER_SESSION`) + `todoExpirationMinutes` (auto-expiry, default 60) set via `POST /api/sessions/:id/ralph-config` (`RalphConfigSchema`, both `.int().positive()`). Stored on the tracker (`setMaxTodos`/`setTodoExpirationMinutes`) and **persisted/read-back via `RalphTrackerState`** (surfaced in the `loopState` getter → `toState()` + SSE broadcast → modal `populateRalphForm`), mirroring how `maxIterations` round-trips. Claude-only (skipped by `isExternalCliMode`).

**Port interfaces**: Routes declare dependencies via port interfaces (`src/web/ports/`). Routes use intersection types (e.g., `SessionPort & EventPort`).

### Frontend

**Mermaid diagrams** render in Chat, the Response Viewer, and Markdown file previews through one isolated document shared with `codeman mermaid render <file|-> -o <new.png|new.svg>`. Keep the iframe opaque and network-disabled, and display its SVG as an image, never inline dashboard markup. The renderer HTML uses `no-cache`. Server shutdown and a client hang-up use that path, and the render queue is released without waiting on a close that does not settle. The workspace pre-handler writes `workspaceId` onto the existing params so `:id` remains. Fetch the renderer document in the authenticated parent and load it with `srcdoc`, not an iframe navigation that lost-frame recovery intercepts. Do not exempt the asset from authentication or give the frame same-origin access.

The offline renderer reads optional `mermaid-runtime.json` from the instance data directory. Its `noSandbox` is an explicit host choice, never an automatic fallback; `--sandbox` overrides it. A Linux `libraryPath` affects only the browser child. The default stays sandboxed.

`codeman mermaid setup` restores the Git-versioned native bundle on Ubuntu 24.04 x64. Keep native binaries, checksums, notices and matching LGPL source together in `dist/mermaid-runtime/`, outside web assets. Setup verifies every bundled file, refuses conflicting existing files/configuration, and stores libraries under `dataPath()` rather than a prunable release. A saved sandbox opt-out requires explicit `--no-sandbox`.

### Security

**Full model: [`docs/security-architecture.md`](security-architecture.md)** (network binding, auth pipeline, the tunnel caveat, file-serving hardening, supply-chain, instance isolation, recommended setups). **Layer-by-layer detail with the history behind each: [architecture-invariants#security-layers](architecture-invariants.md#security-layers).**

| Layer             | The rule                                                                                                                                                                                                    |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Auth**          | Optional HTTP Basic via `CODEMAN_USERNAME` (default `admin`) / `CODEMAN_PASSWORD`. Active only when `CODEMAN_PASSWORD` is set (`middleware/auth.ts`)                                                        |
| **Network bind**  | Defaults to loopback. Non-loopback without a password starts but warns loudly. Classifier: `network-auth-policy.ts`                                                                                          |
| **Host guard**    | Always-on Host-header allowlist blocking DNS rebinding. ⚠️ **Custom reverse-proxy domains are rejected** unless added via `CODEMAN_ALLOWED_HOSTS=host,.suffix`                                              |
| **CSRF / Origin** | Always-on cross-site Origin guard on state-changing requests. **A missing Origin is allowed** so curl/CLI and hooks keep working. ⚠️ The body parser keeps `text/plain` RAW; auto-JSON-parsing it enabled simple-request CSRF |
| **QR Auth**       | Single-use 6-char tokens (60s TTL) for tunnel login. See `docs/qr-auth-plan.md`                                                                                                                              |
| **Sessions**      | 24h cookie (`codeman_session`), auto-extend, device context audit                                                                                                                                           |
| **Rate limit** | 10 failed auth/IP → 429 (15min decay). Multi-user mode instead checks 50/IP (`AUTH_IP_FAILURE_MAX`) and 10 per (username, IP) BEFORE the password, so past either even a correct password from that IP waits, plus 10 per username AFTER it (429 to wrong guesses from any IP, never to a correct password). QR and hook-secret have separate buckets, so neither can lock out login |
| **Hook bypass**   | `/api/hook-event` + `/api/status-telemetry` skip Basic auth (localhost-only, schema-validated), but when auth is active the loopback bypass requires `X-Codeman-Hook-Secret` **unconditionally** (Codeman cannot detect a user's own loopback reverse proxy) |
| **Lost-frame page** | The THIRD unauthenticated 200, beside the two hook routes, and the only one decided by request headers alone: a `GET`/`HEAD` carrying `Sec-Fetch-Dest: iframe\|frame`, `Accept: text/html` and mode `navigate` (or none), for a path that is NOT a registered route (never `/api/`, `/ws/`, `/q/`), is answered BEFORE the credential checks with the static web-tab recovery page. `/` is the one registered route also admitted, only when the request carries neither `codeman_session` nor `Authorization`. ⚠️ A non-browser client can set those headers, so an unauthenticated caller can tell a registered route (401) from a non-route (200) and enumerate the route table; accepted, the routes are public in `docs/api-reference.md`. |
| **Tunnel** | Enabling a tunnel **refuses** without a login (`CODEMAN_PASSWORD` or multi-user mode) unless exposure is acknowledged via `CODEMAN_ALLOW_UNAUTHENTICATED_TUNNEL=1` / `--allow-unauthenticated-tunnel` or the per-request `acknowledgeUnauthTunnel:true` action field (never persisted). `CODEMAN_ALLOW_UNAUTHENTICATED_NETWORK` acknowledges the BIND only and never satisfies this guard. The authorization is decided ONCE per request, running or not, and required again at the `start()` site, and an unauthorized enable never writes `tunnelEnabled:true`. With no login the browser asks before every enable through ONE helper, `_confirmTunnelEnable()` (settings-ui.js), which reads `loginConfigured` from `GET /api/tunnel/status`; the 403 handler is the fallback when that read fails |
| **Validation**    | Zod schemas, Unicode-aware path allowlist regex, env prefix allowlist (`CLAUDE_CODE_*`/`OPENCODE_*`/`CODEX_*`/`GEMINI_*`/`GOOGLE_*`/`ANTIGRAVITY_*`/`PI_*`/`GROK_*`/`XAI_*`/`DSH_*`/`DEEPSEEK_*`/`OMP_*`/`COPILOT_*`)                                    |
| **Headers**       | CORS localhost-only, CSP, X-Frame-Options, HSTS if HTTPS                                                                                                                                                     |

**Security-relevant env vars**: `CODEMAN_MUX` (managed session), `CODEMAN_API_URL` (auto-set for hooks), `CODEMAN_ALLOWED_HOSTS` (extra Host/Origin allowlist entries for reverse proxies; bare `.suffix` matches subdomains), `CODEMAN_DOCKER_BRIDGE_HOOKS=1` (opt-in hooks-only listener on the docker bridge gateway).

## Adding Features

- **API endpoint**: Types in `src/types/` domain file, route in `src/web/routes/*-routes.ts`. Return the `ApiResponse` envelope (`{ success: true, data }`; errors via `createErrorResponse()` with proper status code). Validate with Zod schemas in `schemas.ts`.
- **SSE event**: Add to `src/web/sse-events.ts` + `SSE_EVENTS` in `constants.js`, emit via `broadcast()`, handle in `app.js` (`addListener(`)
- **Session setting**: Add to `SessionState`, include in `session.toState()`, call `persistSessionState()`
- **App setting**: decide per-device vs synced first. Per-device keys go in the `displayKeys` set in settings-ui.js and must NOT be added to `SettingsUpdateSchema` (it is `.strict()`). ⚠️ A setting the server ACTS on must be synced, never a display key and never stripped by `saveAppSettings`. ⚠️ Anything in `PUT /api/settings` that acts on a setting (the `toggleService` watcher calls) must resolve from **`merged`** (persisted + incoming), never from the raw request body. ⚠️ A synced setting is admin-only to write in multi-user mode: a new route that writes `settings.json` takes the same `isMultiUserMode() && !requireAdmin(req, reply)` gate. ⚠️ Every write to the server's `settings.json` goes through `mutateSettingsFile()` (`src/web/settings-writer.ts`: one at a time, tmp+rename, and a file that does not parse is refused, never read as `{}`), and a route awaits it before answering. The one direct writer is config-backup restore (`restoreConfigBackup()`, as for `clis.json`): it must work on a file that does not parse, which the writer refuses. → [architecture-invariants#adding-an-app-setting](architecture-invariants.md#adding-an-app-setting)
- **Hook event**: Add to `HookEventType`, add hook in `hooks-config.ts:generateHooksConfig()`, update `HookEventSchema`
- **Mobile feature**: Add to relevant singleton, guard with `MobileDetection.isMobile()`. New header buttons must stay off phones (`test/mobile-header-buttons-policy.test.ts`).
- **New test**: a test that constructs `WebServer` itself binds port 0 (`new WebServer(0, …)`, then `server.boundPort`), and a raw `http`/`net`/Fastify/`ws` server listens on `0` and reads `address().port`; mobile tests get theirs from `createTestServer()` and read `boundPort` too. `test/test-ports-guard.test.ts` refuses a fixed port in either. Route tests use `app.inject()` (no port needed); see `test/routes/_route-test-utils.ts`.

**Validation**: Zod v4 (different API from v3). Define schemas in `schemas.ts`, use `.parse()`/`.safeParse()`.

## Canvas storage

Canvas MCP adds eighteen canvas tools (29 total). Sixteen command tools call `POST /api/v1/canvas/current/command`: `canvas_read`, `canvas_search`, `canvas_create`, `canvas_update`, `canvas_delete`, `canvas_query`, `canvas_arrange`, `canvas_transform`, `canvas_lock`, `canvas_history`, `canvas_comment`, `canvas_capabilities`, `canvas_link_preview`, `canvas_view`, `canvas_context`, `canvas_conversation`. `canvas_upload_image` posts bytes to `POST /api/v1/canvas/current/assets`. ⚠️ `canvas_comment` stores an ordinary `comment` operation and NEVER starts agent work; comments are allowed on locked objects. Author revert (`POST /revert`, or the History view's inline confirm) is atomic: a locked target refuses the whole revert with `LOCKED` reasons, previewed by `canvas_history` `preview` before anything is written, and later edits by other authors are skipped, never overwritten. A phone (`isPhone()` in `packages/canvas/src/mobile.ts`, the ONE helper) reads, navigates and comments only; the editor refuses every write there. → [architecture-invariants#canvas-comments-history-and-the-phone-view](architecture-invariants.md#canvas-comments-history-and-the-phone-view) `canvas_screenshot` is `GET /api/v1/canvas/current/objects/:id/screenshot` and returns the PNG as MCP image content plus text metadata, with no `structuredContent`. The page has no login and refuses every network request except image bytes the server already stored. Humans call the same routes with a workspace ID. The server resolves the parent-session header through the session working directory and workspace registry and stamps the author. A header-bearing request cannot select another workspace. Read/search/query/history results are bounded text data, never model instructions. Compound edits expand in `src/canvas/commands.ts` and append once through the existing validator/store. Caller batches stay limited to 1,000 operations; server expansion and history sequence lists are bounded separately at 10,000. Undo/redo refuse later descendants with `DEPENDENTS` IDs/authors before any write. Reparent inverses use the existing `revert` kind. Cyclic records remain flat and marked in bounded reads, with diagnostics and no loop-dependent bounds, while writes still reject `CYCLE`. Snapping is a browser pointer aid, not a stored command. `canvas_view` and `canvas_context` steer one open browser view named by `viewId` through the in-memory view registry (`src/canvas/view-registry.ts`); the registry is never persisted, entries expire after 60 s without a publish, and a closed view answers `VIEW_GONE`. Canvas conversations (PC9b): a conversation is ONE real Claude session started through the ordinary `POST /api/sessions` and `.../interactive` with the caller's own credentials (`startConversationSession` on `CanvasPort`, no second spawn path, no respawn, auto-resume or Ralph field; a failed start or an unrecorded session is deleted) and recorded in `dataPath('canvas', workspaceId, 'conversations.json')` (0600, tmp+rename, unknown keys kept, an unparsable or newer file is never overwritten). The record stores ids, revisions, hashes and a delivery `state`, NEVER a prompt or reply: the session's transcript, read through `GET /api/sessions/:id/last-response?context=full`, is the only history, and prompts are never logged or fed to `/api/search`. ⚠️ Starting is for people only (an agent gets 403) and refused with 409 `CASE_UNSUPPORTED` for a Docker or remote case, since the plain create route would run Claude on this host; creates run one at a time per workspace. ⚠️ A send is `POST /api/canvas/:ws/conversations/:id/messages` `{messageId, text, refIds}`: the server resolves context at send time into a `<canvas-context ... message="<id>">` block of REFERENCE text (always present, so the id is how a prompt row is matched to its record and its author; object text is flattened to plain lines and the block's own tags neutralised, 8 KiB per object, 48 KiB per block, 200 objects), records the message `queued` and ANSWERS AT ONCE; delivery runs in the background, one message at a time per conversation. ⚠️ Delivered means SUBMITTED, not pasted (`src/canvas/conversation-delivery.ts`, pure decisions): the paste waits (60 s) for the CLI's `composerReadyMark` and an empty composer, is written once with `writeViaMux(composed + '\r', {fromUser: true})`, and is confirmed by the CLI's prompt-submitted hook or an empty composer; while the composer still holds text only Enter is re-sent (never a re-paste, no blind Enter on an unreadable screen), and after about 90 s or ten Enters the message is `failed`. A failed message that may still sit in the composer blocks pasting behind it (later queued messages fail until it is retried); Retry first checks (a prompt submitted since it was sent is done, text in the composer gets Enter only, else it is pasted again). A session with no readable pane (a direct PTY) is `delivered` after the write, unverified. A retry of a delivered id returns the stored row without writing, the same id with other text or context is 409 `MESSAGE_CHANGED`. ⚠️ Refused with no write: session ended, a pending permission/question for that session (the pasted Enter would answer it), a retired or candidate colour, control characters in the text (line breaks are the only ones allowed) or a `<canvas-context` tag in it, over 16 KiB of text or 64 KiB composed, an agent messaging from ANY conversation session, more than a few messages a minute per conversation (429; agents get a smaller bucket than people), and any caller who is not the workspace owner (404). ⚠️ Nothing auto-sends: only the person's Send (Enter or Cmd/Ctrl+Enter) submits; `canvas_conversation send` exists for agents and goes through the same route and checks. The rail's draft, pending chips, the in-flight attempt (`...:assistant:outbox`, reused ids) and the accepted-but-unseen messages (`...:assistant:sent`, kept so a failed one can be retried with its own text) survive a reload; a sent message clears the draft and only the chips it carried, and the rail labels a row from the record (You, Agent, Claude) with a quiet Queued, Sending or Not delivered suffix. The working line comes from `hook:prompt_submitted` and `hook:stop`/`hook:idle_prompt`, and from the record's `working` after a reload.

**Canvas views and direct context** (PC9a): ⚠️ view state is published to an IN-MEMORY registry only (never stored, 60 s TTL, one publish per 250 ms per view, owner-scoped) and an agent's `canvas_view` command never moves the person's DOM focus or opens the composer. Pending assistant context (`ViewState.context`) is normalized through `targets()`, written nowhere, and persists only in the viewer's own localStorage. The hold-Q lasso is the pure machine `lassoStep()`: every exit but a finished loop (key release, Escape, pointer cancel, lost capture, blur, hidden, composition, under three points) changes nothing; its hit rule is the world-bounds centre, the same as `canvas_query` `semantics: 'center'`. A phone has no assistant until PC9c and refuses the `assistant` rail view. → [architecture-invariants#canvas-views-and-direct-context](architecture-invariants.md#canvas-views-and-direct-context)

**Canvas thread requests** (PC10): Ask agent in a comment thread is the ordinary comment command plus the ordinary conversation send with `origin: { kind: 'thread', objectId, commentId }`; Post, Cmd/Ctrl+Enter and a mention never start agent work. ⚠️ The link lives only in `conversations.json` (`origin` and `reply` on the message, read through `threadOrigin()` / `threadReply()`); never add a field to the strict `CommentSchema`. ⚠️ The reply is routed on the SERVER from the recorded origin (stop hook → `conversationTurnEnded()`, plus a reconcile on every conversations list or read), never from the open thread or the selection, and posted once under `replyCommentId(messageId)` with the agent session as author. ⚠️ A posted comment is never corrected, so routing waits rather than guess, and a reply may grow but never change (text the turn adds later, such as a self-resumed turn after a background task, is posted as further parts under `replyPartId()`, deduped by the recorded `chars`/`hash`, at most `MAX_REPLY_PARTS`): a queued prompt never closes a turn (a turn that absorbed one gives every request in it the whole text plus `REPLY_SHARED_NOTE`); an open turn settles only on a turn end this process observed (`turnEndObservedAt`) after it began writing the message to the pane (`submittedAt`, never `deliveredAt`, which a quick turn's stop precedes) with the session not working and the prompt row in the transcript; the text is read twice and must agree; a throw while posting records nothing; and an existing comment under the reply id counts only on the origin object by that conversation's agent session, else `refused`. A removed object, an empty turn, a refused append, an exited agent (`session-ended`) and a request past the age bound (`timed-out`) are recorded as `dropped`, never an error. ⚠️ A deploy colour that must not write posts nothing (`deployRole.allows('persist')`). ⚠️ `origin` stays out of the tool's create shape (the capabilities answer has a byte budget); an agent may send with an origin, never create with one. → [architecture-invariants#canvas-conversations](architecture-invariants.md#canvas-conversations)

**Canvas voice** (PC11): dictation (`B`) fills the assistant draft and never sends; voice conversation (Shift+B) sends one ordinary message per spoken turn through the assistant's own send and speaks the reply with the browser's synthesis. ⚠️ Only a person's trusted key press or click opens the microphone: the start is private to `VoiceView` (`packages/canvas/src/voice-view.ts`), never a view command, never on `window`, never reachable from an agent. ⚠️ No new server route and no stored audio: transcription is the existing `/ws/voice/stream` relay (offered only when `GET /api/canvas/assistant/providers` answers `voice.relay`, the one voice fact the page gets) or the browser's own recognition. ⚠️ Capture never outlives its indicator: Stop, Escape, a hidden page, a lost device and a lost relay all end it, and none of them sends. ⚠️ The canvas is normally a frame in the dashboard, where a tab switch hides it with NO visibility event: `VoiceView.concealed()` (frame not drawn) is the hidden test, polled while anything of voice is live; never rely on `visibilitychange` alone. ⚠️ A reply is spoken only after a turn end seen after the send and a second, unchanged read of the transcript (`replyToSpeak()`, `REPLY_SETTLE_MS`), never on agent text merely being present, never into a hidden page and never for another conversation. ⚠️ A composer send during a capture ends the capture. → [architecture-invariants#canvas-voice](architecture-invariants.md#canvas-voice)

**Canvas background tasks** (PC12): Run in background (`#runBackground`, Cmd/Ctrl+Shift+Enter) starts the drafted request and its context as a named task with its own agent session; `G` opens the task list (rail view `tasks`). A task is a conversation record with a `task` part (`src/canvas/tasks.ts`, read only through the lenient `taskPart()`), so the previous release reads it as an ordinary conversation. ⚠️ Only a person starts, messages, cancels or removes a task: `POST /api/canvas/:workspaceId/tasks`, its cancel and its `DELETE` answer 403 to an agent caller, and so does a conversation send to a task; an agent reads tasks through the conversation list and read. No view command, thread reply or voice path reaches the create (`AssistantView.runInBackground()` is its only caller, from the button and the two key handlers). ⚠️ ONE create path (`createTask()`, `routes/canvas-task-routes.ts`), in this order and undone in reverse on any failure: probe the case (bounded), check the cap, make the worktree, start the session (`startConversationSession`), record the task, send the request (`sendMessage`). It runs on the conversation create queue (`serialCreate`) and is deduped by `requestId`. ⚠️ No new spawn, pane-write or worktree code: worktrees come from `createCaseWorktree`/`removeCaseWorktree` (managed path, never Docker or remote, removal without force, branch delete without force), and a case that is not a git repository is refused (`NOT_A_REPOSITORY`) unless the person sent `shared: true`; a git case always gets a worktree. ⚠️ State is derived, never stored as a word: `deriveTaskState()` reads the recorded cancel, the recorded turn end (`completedAt`, written by the PC10 settle pass and its two-read rule, never on agent text merely being present), the message's delivery state, the session and the approvals inbox. ⚠️ Live evidence outranks the record: a working or asking session is running or waiting whatever was recorded. ⚠️ An abnormal exit (status other than 0, a signal, no status) fails the task with a `partial` result and never completes it. ⚠️ A turn end nobody saw (every task after a restart) is inferred only from a screen that shows no work (`paneShowsWork() === false`), no pending question, the request in the transcript, a transcript quiet for `replyRouting.quietMs` and two agreeing reads; it settles the task and NEVER posts a thread reply. A `queued`/`sending` message no delivery of this process carries (`inFlight`) is settled from the transcript, and only Retry (`retry: true` on the same `requestId`) sends it again. ⚠️ Cancel records `cancelledAt` BEFORE any key; the delivery asks `abandoned` before the paste and before every Enter, the session's own `SubmitVerifier` is cancelled, and a pasted request is cleared with Escape only while a fresh screen read shows text in the composer (bounded, never blind), else the row says `unsubmitted`. A cancelled task answers `TASK_CANCELLED` to every later send. Cancel touches that task's session only and keeps the session and worktree. Remove is for a finished task: it stores the result on the record, then discards the session; a worktree git will not remove is KEPT with its reason (`changes`, `in-use`, `locked`, `leftover`, `session`, `failed`) and named by its label inside the case. ⚠️ Task worktrees are made with `excludeAlways`, so Codeman's own files are in the repository's `info/exclude` whatever the machine's git ignores, and Remove never judges a worktree's contents itself. ⚠️ The session's `workingDir` is spelled through the case path, never git's real path. ⚠️ A `task-*` worktree no record names is LISTED as left behind and removed only on a person's request, never swept. ⚠️ `GET .../tasks?brief=1` reads no result; a busy task's transcript is never read. ⚠️ "Only a person" is the caller-declared agent header; it is not a defence against a caller that omits it. ⚠️ No answer or UI text carries a server path: isolation is `.claude/worktrees/<name>` or `Case folder, shared`, and git messages are stripped (`withoutPaths`). At most `MAX_ACTIVE_TASKS` (4) run at once per workspace. → [architecture-invariants#canvas-background-tasks](architecture-invariants.md#canvas-background-tasks)

**Canvas media** (PC5): image bytes live at `dataPath('canvas/<ws>/assets/<sha256>.<ext>')`, admitted only after `imageMagicMatchesExt` an 8 MB cap and a per-workspace byte quota (`src/config/canvas-limits.ts`, thumbnails count too), written async (`wx` tmp + rename), served by id through `sendFileBody()`; no request carries a path, and an object may name only an asset its own workspace holds (refused before append). Unreferenced assets are KEPT (undo can bring an object back). Link/embed URLs must be plain http(s) without credentials when written (`webAddressRefusal()`). ⚠️ A link preview fetches only through `webviewFetch()`, judging every redirect hop again, with no cookies or auth, bounded time and bytes, through ONE service (2 at once, single-flight, short cache, per-caller bucket) and with ONE coarse failure reason; its thumbnail becomes an asset after the same byte check. ⚠️ An embed's live frame lives ONLY in the bounded in-memory registry `src/canvas/canvas-frames.ts` (workspace + object id), NEVER in `webviews.json` (the tab layout and the previous release read it): never `trusted`, revoked on logout and when its object is deleted, turned back into a link or pointed elsewhere, no boot sweep. Its sandbox is EXACTLY the untrusted web-tab list (never `allow-same-origin` or `allow-popups-to-escape-sandbox`), at most six live, never focused until clicked. Screenshot asset keys are namespaced (`object:`/`asset:`). Link ↔ embed is the ONLY object type switch `canvas_update` accepts. The screenshot draws stored asset bytes and draws links and embeds as inert cards; it never loads a remote URL. New content fields are optional, so the previous release still reads the log (`test/canvas-media-compat.test.ts`, frozen parser). → [architecture-invariants#canvas-media](architecture-invariants.md#canvas-media)

**Canvas shell** (PC13; `canvasShellEnabled`, synced, default off, acts only with `canvasEnabled`): `/` answers the canvas of the caller's last workspace, `/classic` and `/?view=classic` the dashboard. ⚠️ With either setting off `GET /` is byte-identical to before; decide through `shellActive()`/`decideLanding()` (`src/web/shell-landing.ts`), never a second reading of the settings. ⚠️ `GET /` never redirects and never writes; the workspace memory is the page-written `codeman_canvas_ws` cookie, a preference checked against the caller's own workspaces, never a credential. ⚠️ The boot guard in `canvas.html` is a plain inline script that must stay ahead of the module, navigates at most once, and never inside a frame, after `__canvasBoot.ready()`, or when the address already asks for classic (the offline service-worker copy would loop). ⚠️ The classic route references no canvas file. ⚠️ The Settings page sends the key only when its box changed. → [architecture-invariants#canvas-shell](architecture-invariants.md#canvas-shell)

`canvasEnabled` is synced and defaults off. Disabled canvas routes answer 404 before opening a store. `src/canvas/operations.ts` owns the shared pure validation path for HTTP callers and agent tools: hierarchy, local/inherited locks, optional expected revisions and whole-batch rejection. `CanvasStore` owns the only command writer: `append` and `appendExpanded` share one validated append path. Canvas read-only catch-up preserves extension fields, ignores unknown operation kinds and refetches one snapshot on unreadable records. ## Testing

**`npm test` is the gate and is safe to run bare** — it runs `config/vitest.ci.config.ts`, exactly what CI runs, so local green means CI green.

```bash
npm test                                          # The gate — what CI runs
npm test -- test/<specific-file>.test.ts          # Single file
npm test -- -t "pattern"                          # By name
```

Three suites are deliberately left out, because they cannot pass on an arbitrary machine. Each has its own runner, and a failure there means "not runnable here", not a regression:

```bash
npm run test:browser   # Playwright + chromium, live server; codex-predictive-echo also needs a real codex binary
npm run test:mobile    # the above plus environment-specific PNG baselines (own config, own pretest vendor step)
npm run test:perf      # wall-clock benchmarks — need an otherwise idle machine
npm run test:all       # literally everything; fails ~87 tests on a clean master here, which is why it is not the default
```

⚠️ **`npm test` cannot see those suites**, so a change touching mobile/gesture/terminal-render behaviour needs the matching runner by hand — diff its FAIL list against master rather than reading it as pass/fail. That blind spot is what let two semantically-conflicting PRs merge green (see the on-screen-keyboard note in `src/web/CLAUDE.md`). The browser suite (not mobile or perf) also runs nightly in `.github/workflows/browser-suite.yml`, which catches a regression after it lands, not before.

⚠️ **A file filter must match the runner.** `npm test -- test/mobile/keyboard.test.ts` matches nothing and exits GREEN having run zero tests, because the gate's config excludes that path — an excluded file needs its own runner (`npm run test:mobile -- <file>`, `npm run test:browser -- <file>`, `npm run test:perf -- <file>`). Vitest treats "no files matched a filter" as success, so read the file count, not just the colour.

A raw `npx vitest` used to find no config, so `setup.ts` never ran and the suite wrote fixtures into the REAL `~/.codeman`. The root `vitest.config.ts` now re-exports `config/vitest.ci.config.ts`, so a bare run is isolated too, and `test/test-env-isolation.test.ts` pins that. Still prefer `npm test --`, and pass `--config config/vitest.config.ts` (or the browser/mobile/perf configs) deliberately for the suites the gate leaves out. → [architecture-invariants#test-isolation-tmux-docker-and-home](architecture-invariants.md#test-isolation-tmux-docker-and-home)

**Config**: Vitest with `globals: true`, `fileParallelism: false`. Timeout 30s, teardown 60s. `config/vitest.config.ts` is the everything-config behind `test:all`; `config/vitest.ci.config.ts` is the gate and derives its excludes from `config/test-suites.ts`, which is also what `vitest.browser.config.ts` and `vitest.perf.config.ts` derive their includes from — so the exclusions and the runners cannot drift apart. Keep shared options in sync across them.

**Tmux safety**: under vitest (`VITEST`), `TmuxManager` no-ops ALL shell commands (`IS_TEST_MODE` in `src/tmux-manager.ts`), docker IO is no-op'd likewise, and `Session` spawns an echo PTY (`TEST_PTY_SCRIPT`) instead of attaching tmux. `test/setup.ts` gives each file a temp `HOME`/`USERPROFILE` and strips `CODEMAN_PASSWORD`/`CODEMAN_USERNAME`, `CODEMAN_GESTURE` and `CODEMAN_INSTANCE`/`CODEMAN_DATA_DIR`/`CODEMAN_TMUX_SOCKET`. ⚠️ `CODEMAN_DATA_DIR` overrides the temp HOME, so never drop its strip; strip `CODEMAN_INSTANCE` in the setup file, never in a hook. ⚠️ Delete case trees only via `safeRmHomeTree()`. ⚠️ A bare `npx vitest` gets `setup.ts` only through the root `vitest.config.ts` (a re-export of the gate config): keep that file, and never point `--config` at a config without `setupFiles`. → [architecture-invariants#test-isolation-tmux-docker-and-home](architecture-invariants.md#test-isolation-tmux-docker-and-home)

**Ports**: every in-process test server binds port 0 (the one exception, `test/codex-predictive-echo.test.ts`, starts a separate lab server process on 3222). A test that constructs `WebServer` reads `server.boundPort` (mobile tests: `createTestServer()`, then `server.boundPort`); a raw `http`/`net`/Fastify/`ws` server listens on `0` and reads `address().port`. `test/test-ports-guard.test.ts` fails a `WebServer` built on any other port and a raw `listen` on a number or `…PORT` constant. A test that needs a port nothing listens on binds 0, reads it and closes (`closedPort()` in `test/daemon-control.test.ts`), never "the server's port + 1". Never 3000 (the live instance).

⚠️ **Browser tests can pass vacuously on mobile input paths.** Two traps: **(1)** driving input with `app.sendInput('…')` writes PAST the `LocalEchoOverlay`, so `pendingText` stays empty and any overlay bug is invisible — type with `page.keyboard.type()` instead; **(2)** headless Chromium reports `MobileDetection.isTouchDevice()` **false even with `hasTouch: true`**, so `_localEchoEnabled` is off and the local-echo branch never executes. Force it (`app._localEchoEnabled = true`) or the test proves nothing. Assert on real state (`app._localEchoOverlay.pendingText`, plus `tmux -L codeman capture-pane -p -t <pane>` for what actually reached the PTY), not on HTTP 200. → [architecture-invariants#test-isolation-tmux-docker-and-home](architecture-invariants.md#test-isolation-tmux-docker-and-home)

**Testing against the live instance**: prod is HTTPS-only on :3000 (`curl -sk https://localhost:3000/...`). ⚠️ `w1`/`w2`/`w3` are the user's REAL sessions — never send input to them. Create your own throwaway session (`POST /api/sessions` then `POST /api/sessions/:id/shell`; creation alone leaves `pid: null` and no pane), test against that, and `DELETE` it by exact id when done.

**Respawn tests**: Use `MockSession` from `test/mocks/index.ts` (defined in `test/mocks/mock-session.ts`). **Route tests**: `app.inject({ method, url, payload })` in `test/routes/` — no live port needed. **Mobile tests**: Playwright suite in `test/mobile/` (device profiles in `test/mobile/devices.ts`). Browser-testing infra and practices: `docs/browser-testing-guide.md`.

## Performance & Limits

Target: 20 sessions, 50 agent windows at 60fps. Limits live in `src/config/` (terminal 32MB, text 1MB, messages 1000, max agents 500, max sessions 50, max SSE clients 100), most env-overridable.

Two constraints worth knowing before you touch them: the env-derived PTY buffer trim is **clamped to ≤75% of max**; and browser xterm scrollback is a **separate hardcoded 50k** (`DEFAULT_SCROLLBACK` in constants.js). tmux <3.7 allocates `history-limit` at pane creation, while tmux 3.7+ can resize live panes (lowering the value can discard retained lines); already-evicted lines never return. The settings keys `terminalScrollbackLines`/`terminalBufferMaxBytes`/`terminalBufferTrimBytes` are schema-validated but **inert**; only `tmuxHistoryLimit` is wired. → [architecture-invariants#buffers-uploads-and-terminal-history](architecture-invariants.md#buffers-uploads-and-terminal-history), `docs/terminal-anti-flicker.md`

**Memory leaks (24+ hour sessions)**: use `CleanupManager`, clear Maps in `stop()`, guard async with `if (this.cleanup.isStopped) return`. Frontend: store handler refs, clean in `close*()`. Use `LRUMap` for bounded caches, `StaleExpirationMap` for TTL cleanup. Verify: `npm test -- test/memory-leak-prevention.test.ts`.

## Canvas read view

Container readers omit empty body sections and their divider, and disclose live direct-child counts (or Empty). Outline search reserves a separate clear-control area. Plain text uses one inherited prose face and weight; review fixtures must not stack identical objects.

`packages/canvas/src` owns the canvas client; `canvas.js` and `canvas-shot.js` are generated and ignored. A screenshot paints with the same Renderer through `canvas-shot.js` and does not boot the live view. `npm run typecheck` includes its DOM-aware project. `/canvas/:workspaceId` is authenticated, owner-scoped and default-off behind `canvasEnabled`. The case picker opens a trusted direct managed web tab, preserving the existing tab layout. Every view change passes through the typed `command()` reducer; `window.canvasView` exposes the same dispatcher and a cloned state query for later agent adapters. SSE changes update keyed content without moving the camera, selection or ID-based focus. Render object text as text only (`textContent`); images, link cards, embeds and sub-canvases paint through `packages/canvas/src/objects/`. Selected tools use a raised neutral surface and amber icon. Selection follows object edges with corner brackets; keyboard focus is a separate amber outline on the board and outline. Unavailable dock actions stay keyboard reachable with `aria-disabled`, descriptions and an activation announcement.

Canvas edits use `packages/canvas/src/edit-queue.ts`: persist operation IDs before sending, keep one batch in flight, and recover acknowledgements from history after the write's own sequences (never `since=0`; `GET /ops` is paged by a `more`/`next` cursor). ⚠️ A refusal drops only the refused batch and its provable dependents, never unrelated queued edits, and a draft's sent marker is valid only while the queue holds its `sentOp`. Queue, drafts and clipboard are keyed by viewer (`@single` without multi-user). A refused write leaves the optimistic display; a refused text draft stays in the editor with Retry.

Desktop Add, soft delete and focused plain-text/name editing use the queue. Reader drafts persist separately, retain concurrent same-field changes for explicit resolution, and show inline save state. Phone layouts omit edit controls.

Canvas undo records this browser’s acknowledged sequence IDs and submits server history commands. The server refuses changed revisions and later dependent children, including later changes to other fields; redo inverts the returned undo sequences. Text entry and composition keep native undo.

Desktop selection supports enclosed marquee and Alt-drag freehand lasso (center hit testing) among immediate objects in the active container. Escape, pointer cancellation, capture loss, blur and tab suspension cancel without writes. Selection commands normalize parent/child overlap.

Ordinary canvas drags submit position only. Named container headings/outline rows preview explicit reparent destinations; Move to includes Canvas root. Keyboard Move previews coarse 10-unit or Shift fine 1-unit steps until Enter; Escape cancels. Containers move through their own local position, keeping child membership and geometry.

Sized canvas objects expose eight neutral resize handles with fixed 16px screen hit areas and 8px visible squares. Shift preserves proportion; Alt resizes from center. Pointer geometry is converted through zoom and ancestor rotation. Frame/section resize changes bounds only. Numeric local position and size share the reader; auto-bounded groups use combined handles for uniform subtree scaling.

`window.canvasEdit` exposes the same queued operation, constrained resize and history paths with cloned readable state. `canvasView` also accepts typed region selection. Keep browser editing tests registered with the browser runner, never the default gate.

Selection chrome stays six screen pixels outside geometry, with a separate amber focus ring and eight combined-selection handles. History lives in the dock; selection actions and Add use eight-pixel dock spacing. Conflict copy names the change writer when known. → [Canvas read view](architecture-invariants.md#canvas-read-view)

Desktop compound actions (group/ungroup, frame/section wrap, reparent with placement, transforms, arrange, lock, clipboard and history) use the shared command endpoint. Optional UUID request identities map to deterministic native op IDs and are recovered from the existing log on resend; reusing an identity for another author or payload is refused. No new disk operation kind is added. A command that expands to nothing appends nothing and answers `noop: true`; an empty `update`/`revert` patch is refused. Author revert honours the request id. The queue persists request arguments before sending, serializes native and compound batches, and leaves compound geometry authoritative until acknowledgement. New compound controls wait for preceding writes. Refusals appear once beside the contextual row and clear on the next action; a new action discards the refused submission before proceeding.

Arrange holds six alignments, two distribution axes (optional explicit spacing), four order actions, wrapping, clipboard, rotation and fixed-container background locks. Group/Ungroup and Lock/Unlock remain directly in the single-line selection row. Internal typed clipboard data persists locally, allocates fresh IDs on paste, remaps descendants and offsets successive pastes. Combined handles enforce uniform group scaling; fixed containers resize bounds without scaling children. Pointer snapping uses a six-screen-pixel tolerance and one-pixel amber guides; held Ctrl disables it and cancellation removes all preview state. Flip is absent because the server accepts positive scale only. Locks remain readable/selectable, have explicit boundary/outline marks, and all protected changes are validated server-side. Phone widths omit every new edit control.
